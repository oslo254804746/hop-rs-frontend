# Hop 管理面板设计规范

状态：已实现并通过独立视觉验收
日期：2026-08-14
视觉决策：A 作为全局壳，B 作为资产页

## 1. 设计目标

Hop 管理面板是 `/api/v1` 的独立、可替换操作界面，不是新的身份系统，也不改变 Hop v0.2 的单一管理信任域。它服务于个人开发者、家庭实验室维护者和小团队，首要任务是让用户快速回答三个问题：实例是否正常、Catalog 当前是什么状态、下一步需要处理什么。

界面采用 Operate 模式。信息密度可以高，但必须保持清晰、可键盘操作，并让危险操作、声明式所有权和密钥边界一眼可辨。

## 2. 组合方向

### A：全局壳

参考图：`../.impeccable/mocks/overview-operations-rail.png`

A 定义所有路由共享的结构：

- 桌面端使用可收起左侧导航，包含 Overview、Assets、Credentials、Access、Sessions、Configuration。
- 顶部区域显示当前页面名称及少量全局操作，不再重复一套产品导航。
- 左下连接卡持续显示连接模式、实例地址或 Demo 标记、版本及断开入口。
- Overview 首屏以单一健康带为视觉锚点，依次呈现实例健康、版本、Catalog revision 和活动会话。
- 资源摘要、近期会话和配置来源围绕健康带展开，不使用同权重的“指标卡墙”。
- 移动端将侧栏转换为底部导航；次要入口放入 More，不把桌面布局简单压窄。

### B：资产页

参考图：`../.impeccable/mocks/assets-resource-workspace.png`

B 定义资产页的主从工作区：

- 桌面端由上下文筛选栏、资产清单和持久详情检查器组成。
- 清单是页面主区域；行选择立即更新详情，不弹出阻断式模态框。
- 筛选维度仅采用真实可解释字段：协议、所有权、凭据状态与文本搜索。
- 详情检查器显示协议、地址、凭据、时间戳和允许执行的动作；只有 transport 明确提供时才显示来源。
- Demo transport 可演示声明式所有权；当前真实 API 的 list response 没有 source 元数据，因此不能预先伪造来源或禁用动作。若 mutation 返回 `managed_by_source`，界面就地显示来源并停止重试。
- 本地资源允许编辑或删除；删除必须经过包含资源名的确认步骤。
- 移动端变为列表优先，详情作为可返回的全屏层；筛选进入底部抽屉。

参考图中的 `Connect`、`Test connection` 和“查看遮蔽 Access Key”等动作不属于当前 `/api/v1` 合约，首版不实现，也不展示伪按钮。可真实支持的动作包括创建、编辑、删除本地资产，以及跳转查看相关会话。

## 3. 信息架构

| 路由 | 用户任务 | 核心内容 | 主要动作 |
| --- | --- | --- | --- |
| `/` | 判断实例是否需要关注 | 健康、版本、revision、资源数量、活动/近期会话、配置来源 | 刷新、进入问题所在页面 |
| `/assets` | 管理 SSH/TCP 目标 | 搜索与筛选、清单、凭据状态、可用时的所有权、详情 | 新建、编辑、删除本地资产 |
| `/credentials` | 管理目标凭据 | 类型、用户名、密钥是否已配置、可用时的所有权 | 新建、轮换、删除本地凭据 |
| `/access` | 管理入口密钥与资产范围 | 启用状态、all/restricted/empty scope、可用时的所有权 | 新建、启停、更新范围、撤销 |
| `/sessions` | 观察并中止活动连接 | 开始时间、资产、协议、Access Key、状态 | 中止活动会话 |
| `/configuration` | 管理声明式配置生命周期 | sources、orphans、schema、revision、diff | 校验、差异、应用、重载 |

连接设置作为全局层，而不是独立主导航页面。首次打开显示连接引导，可在 Demo 数据和真实实例之间切换。真实连接收集 Control API URL 与 Bearer Token；URL 可保存在 `sessionStorage`，Token 仅保存在内存中并在刷新后要求重新输入。应用绝不写入 `localStorage`。

## 4. 视觉系统

### 场景与色彩

用户通常在终端、编辑器和路由器管理页旁边长时间使用面板，因此默认采用低眩光深色界面，同时提供完整浅色主题并跟随系统首选项。色彩策略为 Restrained：石墨/蓝炭中性色覆盖主体，只用一种薄荷绿表达正常和可执行状态；琥珀用于警告；红色只用于失败或破坏性操作。

建议 token：

- `--surface-canvas`: `#0d141d`
- `--surface-rail`: `#111b27`
- `--surface-panel`: `#172231`
- `--surface-raised`: `#1c2939`
- `--line`: `#2a394b`
- `--text-strong`: `#edf3f7`
- `--text`: `#c2ccd6`
- `--text-muted`: `#8795a5`
- `--accent`: `#53c7a2`
- `--warning`: `#f2b84b`
- `--danger`: `#f26464`
- `--info`: `#71b7f4`

浅色主题必须逐项映射语义 token，而不是对深色值做滤镜反转。

### 字体与数字

- UI 使用系统工作字体栈：`ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
- 版本、revision、端口、持续时间和计数启用 tabular numerals。
- 页面标题保持 20–24px；表格正文 13–14px；不得以巨大标题牺牲工作区。
- 仅技术标识符使用等宽字体，普通标签不使用全大写与过度字距。

### 组件语法

- 面板圆角 10–12px，控件 8px；同一层级保持一致。
- 主要分区依靠 1px 分隔线、底色差和留白，几乎不使用阴影。
- 表格行高 48–56px，支持明确 hover、selected、focus-visible 状态。
- 状态同时使用图标/文字与颜色，不能只有彩色圆点。
- 按钮层级为 primary、secondary、quiet、danger；主动作每个工作区最多一个。
- Toast 用于非阻断结果；影响 revision、所有权或密钥的一次性信息必须留在上下文内。
- 抽屉/对话框必须有标题、关闭按钮、初始焦点、焦点圈定与 Esc 行为。

## 5. 关键交互

### 连接与 Demo

1. 首次访问默认进入明确标注的 Demo 模式，用户无需后端即可理解产品。
2. 全局连接卡打开连接层，输入 URL 和 Token 后先请求 `/api/v1/status`。
3. 成功后切换为真实数据并清除 Demo 查询缓存；失败时保留输入并显示可操作错误。
4. 刷新页面后只恢复 URL，不恢复 Token；界面显示“需要重新认证”，不悄悄退回 Demo。

### Catalog 写入

- 所有 mutation 完成后只失效相关查询和 Overview 摘要。
- `409` revision 冲突必须显示服务器最新 revision，并要求重新 diff；不可自动覆盖。
- `409 managed_by_source` 显示来源并引导用户编辑声明式配置。
- 新建 Access Key 接收用户已有的 OpenSSH public key；Hop 不生成或返回 private key，界面必须在提交前说明这一点。
- 凭据读取永不期待 secret 回显；轮换表单只接受新 secret。

### 空态、加载和错误

- 首次加载使用与最终结构一致的骨架，不用全屏 spinner。
- 真正没有资源时提供一个明确主动作；筛选无结果时提供“清除筛选”。
- 页面级 API 失败保留壳和旧数据，显示重试入口与请求目标。
- 离线/断开作为全局状态；危险 mutation 在断开时禁用并解释原因。

## 6. 响应式与可访问性

- ≥1536px：完整侧栏；Assets 可同时显示页面级筛选栏、清单和详情检查器。
- 1200–1535px：全局导航收为图标栏；Assets 筛选进入 popover，保留清单和详情检查器。
- 900–1199px：图标栏；Assets 以清单为主，详情作为可关闭侧层。
- <900px：底部导航；单列内容；表格转为可扫描资源行，详情为全屏层。
- 最小可交互尺寸 44×44px；键盘焦点始终可见。
- 语义化 landmark、标题层级、表单 label、错误关联与实时区域必须完整。
- 支持 `prefers-reduced-motion`；动画只表达层级切换、详情进入和数据更新。
- 桌面和移动端都不得出现横向页面滚动；宽表格在容器内转换或滚动。

## 7. 非目标

- 不实现登录、账户、角色、RBAC、多租户或 OAuth。
- 不让 `hop-rs` 托管静态资源，不把前端构建塞进 Rust 发布流程。
- 不直连 SQLite，不在 UCI 中复制 Catalog。
- 不实现后端尚未提供的连通性探测、SSH 终端或日志流。
- 不复制 Zashboard 的 Mihomo 内容、品牌、图标或页面组织。

## 8. 设计验收

- A 壳在六个路由中保持一致，真实/Demo/断开状态清晰。
- Overview 首屏 5 秒内能读出健康、版本、revision 和活动会话。
- Assets 的选择状态进入 URL；桌面无需模态框即可完成浏览与上下文判断，移动端可用浏览器返回恢复列表位置。
- 当 transport 提供所有权时，声明式资源显示来源且不能被误编辑；当前真实 API 通过 mutation 冲突揭示来源时，界面必须停止操作并解释。所有 secret 边界都符合后端契约。
- 键盘、深浅主题、375px 手机与 1440px 桌面通过视觉和交互检查。
- 静态生产构建不依赖 Node 运行时，并可配置 API base URL。
